## 1번 — 그룹 크기 및 초기 설정·주소 규칙 정의

### 목적과 변경 파일

앞으로 구현할 log-structured 매핑 인덱스의 관리 단위와 공통 설정을 정의했다.

- 생성: `firmware/leaftl/src/leaftl_config.h`
- 생성: [#1단계 - 설정과 주소 계약.md](%231%EB%8B%A8%EA%B3%84%20-%20%EC%84%A4%EC%A0%95%EA%B3%BC%20%EC%A3%BC%EC%86%8C%20%EA%B3%84%EC%95%BD.md) — 주소 체계와 설정의 상세 근거
- 기존 DFTL 소스와 실행 경로는 변경하지 않았다.

### 1. log-structured 인덱스의 그룹 크기 지정

`LEAFTL_GROUP_SIZE = 256`으로 정의했다. 한 그룹은 연속된 LPN 256개를 담당한다.
이는 세그먼트 개수나 레벨 개수를 뜻하지 않는다. 마지막 그룹은 실제 주소 개수에
따라 일부만 사용될 수 있다.

```
그룹 0: LPN   0~255
그룹 1: LPN 256~511
그룹 2: LPN 512~767
```

이후 구현할 구조는 `그룹 → 레벨 → 세그먼트`이다. 각 그룹이 독립적인 여러 레벨을
갖고, 각 레벨에 해당 그룹 주소의 매핑을 표현하는 세그먼트들이 들어간다.
그룹 안의 매핑이 규칙적이면 적은 세그먼트로 표현하고 불규칙하면 더 나누어 표현한다.
매핑 갱신에 따라 여러 레벨에 이전 세그먼트가 남을 수 있다.

그룹 내부 위치를 0~255의 1바이트 offset으로 표현하기 위한 계산 매크로를 추가했다.

| 매크로 | 의미 |
|---|---|
| `LEAFTL_GROUP_ID(lpn)` | `lpn / 256`으로 그룹 번호 계산 |
| `LEAFTL_GROUP_OFFSET(lpn)` | `lpn % 256`으로 그룹 내부 위치 계산 |
| `LEAFTL_GROUP_COUNT(lpn_count)` | 관리할 LPN 개수에 필요한 그룹 수 계산. 덧셈 overflow 방지 |

예를 들어 LPN 300은 그룹 1의 offset 44이다.

**현재는 그룹 크기와 계산 규칙만 정의했다. 그룹 자료구조, 다중 레벨,
최신 매핑 우선 조회, merge·compaction은 아직 구현하지 않았다.**

### 2. 초기 정확 조회 설정

- `LEAFTL_GAMMA = 0`: 초기 버전에서는 예측 오차를 허용하지 않도록 설정했다.
- CRB·OOB 이웃 규칙·오예측 보정이 준비되기 전 `gamma>0` 설정은 컴파일 오류로 차단한다.
- 실제 학습·조회 알고리즘은 2번부터 구현한다.

### 3. 학습에 사용할 주소 규칙 확정

- host LBA는 4 KiB, 논리 슬라이스와 NAND page data는 각각 16 KiB임을 기존 코드에서 확인했다.
- 모델 입력 x는 그룹 내부 offset, 출력 y는 기존 VSA 정수로 정했다.
- 초기 모델의 PPN은 VSA를 의미한다. 실제 NAND row로의 변환은 기존 VSA 변환 경로를 사용한다.
- VSA는 die를 섞어 번호를 부여하므로 `VSA±1`을 같은 die·block의 물리 이웃으로
  취급하지 않는다고 명시했다. gamma>0의 이웃 좌표와 OOB 처리는 후속 단계에서 확정한다.
- 아직 주소 변환 함수나 물리 할당 정책을 변경한 것은 아니다.

### 4. 자원 상한과 메모리 예산 정의

| 설정 | 초기값 | 의미 |
|---|---:|---|
| 상주 그룹 수 상한 | 256 | 전체 그룹 수와 별개인 캐시 상한 |
| 그룹별 레벨 수 상한 | 256 | 여러 버전의 세그먼트를 관리할 레벨 한도 |
| 그룹별 세그먼트 수 상한 | 1,024 | 이전 레벨까지 포함한 한도 |
| 전체 상주 세그먼트 수 상한 | 65,536 | 상주 그룹들이 공유하는 총 한도 |
| 한 번의 그룹 단위 학습 입력 상한 | 256 | 임시 학습 입력 개수 |
| 그룹별 CRB 고유 LPN 수 상한 | 256 | 향후 CRB를 위한 상한 정의 |
| 그룹별 CRB byte 예산 | 512 bytes | 구분자 포함 예산이며 저장 형식은 미정 |
| 추가 LeaFTL 메타데이터 RAM 예산 | 8 MiB | 디렉터리·세그먼트·CRB·관리 정보·임시 공간 포함 |
| 세그먼트 저장 크기 목표 | 8 bytes | 논문 형식 목표이며 실제 C 구조체 크기를 의미하지 않음 |

이 값들은 초기 설정이다. 배열 할당, allocator, CRB, 메모리 배치는 아직 구현하지 않았다.
6번에서 실제 자료구조 크기와 기존 map·버퍼를 포함한 전체 DRAM 사용량을 계산한다.
한도에 도달하면 유효 매핑을 버리지 않고 compaction·writeback·eviction 또는
명시적 실패로 처리해야 한다는 규칙을 문서화했다. 해당 동작은 후속 단계에서 구현한다.

### 5. 자료형과 잘못된 설정 검사

- 8-bit byte와 32-bit unsigned int 환경인지 컴파일 시 확인한다.
- 미매핑 주소 표식으로 `0xffffffffU`를 정의했다.
- 상주 그룹 0개, 허용 범위 밖 레벨 수, singleton 256개를 수용하지 못하는
  그룹별 세그먼트 한도, 부족한 총 세그먼트 pool, RAM 예산 0을 컴파일 오류로 차단한다.
- BSP를 include하지 않는 헤더로 작성하여 다음 단계의 PC용 순수 C 모듈에서 사용할 수 있게 했다.

### 검증 결과

1번 작업 당시 MSVC C 모드 `/W4 /WX /Zs`로 검증했다.

- 통과: 헤더 중복 include, 그룹 경계 255/256, offset 0/255,
  빈 그룹·부분 그룹·전체 그룹의 개수, UINT_MAX에서의 그룹 수 계산.

- SDK 펌웨어 전체 빌드와 보드 업로드는 수행하지 않았다.

## 2번 — 부동소수점 학습·float16 기울기 기반 정확 세그먼트

기록일: 2026-11-12 (사용자 요청에 따라 부동소수점 방식으로 수정)

### 목적과 변경 파일

한 그룹의 LPN→VSA 매핑을 학습하고 `gamma=0`으로 정확하게 조회하는 순수 C
모듈을 구현했다. 최초 정수 분자/분모 모델은 이번 수정으로 교체했다.
아래 설명과 검증 결과는 현재 부동소수점 구현을 기준으로 한다.

- `firmware/leaftl/src/leaftl_segment.h`: 런타임 모델과 공개 API
- `firmware/leaftl/src/leaftl_segment.c`: 부동소수점 PLR, float16 변환, 소속 판정·예측
- `tests/test_leaftl_segment.c`: 주소 정답 map 대조, 양자화·오류·경계 테스트
- `tests/verify_float16.py`: 컴파일한 C 변환기를 Python binary16 변환과 독립 비교
- [tests/README.md](../../firmware/LeaFTL/tests/README.md): 실행 방법과 연산 계약
- 이 보고서: 기존 정수 분수 방식 설명을 현재 구현으로 갱신

기존 DFTL 실행 경로와 `leaftl_config.h`는 변경하지 않았다.

### 주요 구현 내용

**1. 부동소수점 구간별 선형 학습**

`LeaFtlSegmentTrain()`은 한 그룹에 속하고 LPN이 엄격히 증가하는 최대 256개의
매핑을 받는다. 학습의 기울기 범위 계산과 절편 계산은 `double` 부동소수점으로
수행한다. 정수 분자/분모를 저장하거나 정수 나눗셈으로 모델을 평가하지 않는다.

```
x = 그룹 내부 offset (0..255)
K = 저장된 binary16 기울기를 double로 복원한 값
예측 PPN = ceil(K * x + I)
```

모든 입력 쌍의 `ceil` 조건으로부터 가능한 기울기 구간을 누적 교차한다.
`i<j`, `dx=xj-xi`, `dy=yj-yi`일 때 `(dy-1)/dx < K < (dy+1)/dx` 조건을 사용한다.
가능 구간의 중간 기울기를 float16으로 양자화하고, 그 기울기에 맞춰 절편을 다시
계산한다. 양자화된 실제 모델로 모든 점을 다시 예측하여 입력 PPN과 정확하게
일치할 때만 세그먼트를 확장한다.

범위가 비거나 양자화·검증에 실패하면 세그먼트를 분할한다. 한 점은 K=0과
해당 PPN 절편으로 표현한다. 단일 OLS나 최소 세그먼트 수 보장 알고리즘은 아니다.
양자화한 중간 기울기가 실패하면 다른 가능한 float16 기울기를 전수 탐색하지 않고
분할하므로 압축에 보수적인 구현이다.

**2. 실제 float16 기울기 저장 및 재검증**

기울기는 `uint16_t slope_bits`에 IEEE-754 binary16 인코딩으로 저장한다.
정수 비트 컨테이너를 쓰는 것이며 고정소수점 기울기를 뜻하지 않는다.
별도의 고정밀 기울기를 숨겨 두고 예측에 사용하는 방식도 아니다.

`LeaFtlFloat16Encode/Decode()`를 추가했다. nearest/ties-to-even, signed zero,
subnormal, infinity, NaN을 처리하며 네이티브 float16 명령이나 자료형을 요구하지 않는다.
학습된 세그먼트는 NaN/infinity 기울기를 허용하지 않는다.

논문의 형식처럼 기울기 최하위 비트를 segment type용으로 예약했다.
현재 exact segment이므로 이 비트는 0으로 만들고, 그 이후 기울기로 절편을 다시
맞추고 전체 입력을 재검사한다. 아직 approximate type=1은 지원하지 않는다.
양자화나 type 비트 때문에 부정확해지는 모델을 그대로 발행하지 않는다.

예를 들어 기울기 65504는 finite float16이지만 최하위 type 비트를 0으로 만들면
기울기가 달라진다. 이 기울기가 필요한 입력은 재검증에서 거부하여 singleton으로
분할하는 회귀 테스트를 추가했다.

**3. hole과 잘못된 주소 처리**

`LeaFtlSegmentContains()`는 그룹, 시작·끝 offset, 명시적 stride를 검사한다.
LPN 간격이 바뀌면 분할하므로 범위 안의 hole을 유효 주소로 취급하지 않는다.
PPN의 증가·감소·반복을 처리하며, 다른 그룹/hole은 MISS로 반환한다.

`LeaFtlSegmentPredict()`는 모델·소속·예측 범위를 검사한 후에만 정수 PPN을
반환한다. NaN/infinity 절편·기울기, 잘못된 type·stride, 음수·overflow·sentinel
출력은 차단한다. PPN 0은 유효하다. 실패 시 PPN 출력값을 바꾸지 않는다.

학습 입력의 중복·역순·그룹 혼합·sentinel·잘못된 포인터를 거부한다.
상위 계층은 최신 쓰기 선택과 그룹 분리를 먼저 수행해야 한다.
필요한 출력 개수를 먼저 계산해 공간 부족 시 부분 발행하지 않는다.
동적 할당과 전역 가변 상태를 사용하지 않는다.

**4. 현재 수치 표현과 논문과의 관계**

공개 구현의 PLR과 float16 기울기 저장을 참고하고, 예측은 이식 계획에 정한
논문의 `ceil(K*x+I)`를 따른다. 공개 시뮬레이터는 `round`를 사용하므로 그 소스를
그대로 복사한 구현은 아니다. 참고:
[공개 learnedftl.py](https://github.com/platformxlab/LeaFTL/blob/main/wiscsee/wiscsim/learnedftl.py).

학습·조회는 유효 정밀도 53-bit 이상의 binary `double`을 사용한다.
float32는 2^24보다 큰 모든 정수 PPN을 정확히 표현하지 못하므로 현재 절편 I도
double로 보관한다. 20,000,001 및 32-bit 상한 근처의 주소를 별도로 검사했다.
기울기 자체는 실제 binary16으로 제한된다.

현재 MSVC x64의 런타임 구조체 크기는 24 bytes이며, 논문의 8-byte 전체 인코딩은
아직 구현하지 않았다. 논문의 4-byte 절편과 달리 현재는 double 절편을 사용하는
점이 남아 있다. 6번에서 실제 타깃 메모리를 계산하고, 11번에서 절편을 포함한
직렬화·압축 표현을 설계하고 표현 변환 후에도 동일한 오차 검증을 수행한다.

기존 VSA 할당을 유지하므로 음수/큰 기울기도 입력될 수 있다. float16으로
표현할 수 없는 경우 안전하게 분할한다. 논문의 물리 배치·압축률과 동일하다고
가정하지 않는다. gamma>0은 기존 설정대로 차단한다.

### SSD 타깃에서 고정소수점으로 전환할 가능성

사용자가 SSD에 올릴 때 고정소수점 연산만 가능할 수 있다고 알렸다.
현재 요구에 따라 PC 구현은 부동소수점으로 유지하지만, 타깃의 FPU·컴파일러·BSP와
연산 비용을 확인한 후 고정소수점 또는 다른 소프트웨어 수치 구현으로 변경할 수 있다.
현재 보드에서 부동소수점 실행을 확인한 것은 아니다.

전환 시 다음을 수행한다.

- 외부 학습/조회 API와 그룹·membership 계약은 가능한 유지하고 수치 연산부를 교체한다.
- 기울기·절편의 배율, 정수/소수 비트 수, 중간 곱셈 폭, overflow와 포화 정책을 명시한다.
- 양수·음수의 ceil과 경계값을 보장하고 float16 저장 형식과 고정소수점 실행 형식의
  변환을 구분한다. 저장 기울기를 바꾸면 그 값으로 다시 학습 검증한다.
- 기존 정답 map 테스트와 hole/주소 상한/양자화/실패 시 부분 발행 금지 테스트를
  모두 재실행한다. 표현할 수 없는 구간은 안전하게 분할한다.
- SDK 빌드·타깃 비용 검증 결과와 필요 시 저장 형식 버전 변경을 이 보고서에 기록한다.

고정소수점 지원은 현재 구현 완료 항목이 아니며, 향후 타깃 확인 후의 변경 가능성이다.
현재 구현은 `math.h`와 엄격한 부동소수점 의미론에 의존한다. fast-math는 사용하지 않는다.
GCC/Clang은 `-lm` 링크가 필요할 수 있고 SDK에서도 관련 수학 런타임을 확인해야 한다.

### 수정 후 검증 결과

MSVC C11, `/W4 /WX /fp:strict`로 경고 없이 빌드했다.
debug(`/Od /Zi`)와 optimized(`/O2`)에서 다음 검증을 수행했다.

- 6,638개 배치에서 각각 그룹의 모든 256개 offset을 정답 map과 비교했다.
  실제 저장된 float16 기울기와 절편으로 계산한 결과도 직접 대조했다.
- 순차 256개, 모든 stride 1..255, 불규칙 hole, singleton, PPN 0·상수,
  감소·비단조 주소, 최상위 부분 그룹을 검사했다.
- 길이 1..5/PPN 0..3 조합 전수, 결정적 난수 sparse 배치 4,000개,
  분수 선형 배치 1,000개를 검사했다. 양자화에 따른 추가 분할을 허용하되
  반환값의 정확성은 모든 입력에서 요구했다.
- 양수·음수 ceil, float16 양자화/type 비트 변경 후 분할, 최대 주소 차이,
  2^24 초과 주소와 0xfffffffe 주소, NaN/infinity/잘못된 모델을 검사했다.
- 중복·역순·그룹 혼합·sentinel 입력, 출력 공간 부족, 이전 모델을 유지한 재학습을 검사했다.
- 컴파일한 C float16 변환기를 Python의 독립 `struct` binary16 변환과 비교했다.
  전체 65,536개 비트 패턴, 인접 finite half 값의 중간점 및 양옆 double,
  양·음수 반올림·underflow·overflow 경계를 포함해 총 321,548건이 일치했다.

정답 map과 Python 검증기는 테스트 전용이다. 실제 모델은 이들을 참조하지 않는다.
SDK 전체 빌드, 보드 업로드, 타깃 FPU·성능 및 고정소수점 지원 여부는 미검증이다.

## 3번 — 그룹별 다중 레벨 인덱스와 최신 매핑 우선 조회

기록일: 2026-11-12

### 목적과 변경 파일

2번 float16 기울기 세그먼트를 그룹별 log-structured 인덱스로 관리하고,
여러 번 갱신된 LPN에서 최신 매핑을 선택하는 기능을 구현했다.

- 생성: `firmware/leaftl/src/leaftl_index.h` — 그룹·레벨·노드 및 API 계약
- 생성: `firmware/leaftl/src/leaftl_index.c` — 초기화·삽입·조회·그룹 정보 조회
- 생성: `tests/test_leaftl_index.c` — 버전·hole·자원 부족·무작위 갱신 통합 테스트
- 갱신: [tests/README.md](../../firmware/LeaFTL/tests/README.md) — 3번 재실행 방법과 검증 범위
- 갱신: 이 구현 보고서

기존 `leaftl_config.h`, 부동소수점 `leaftl_segment.c/h`와 DFTL 실행 경로는
변경하지 않았다. 8-byte 저장 형식은 이번 단계에서 구현하지 않았다.

### 주요 구현 내용

**1. 그룹 → 레벨 → 세그먼트 구조**

`LeaFtlIndexInit()`에서 호출자가 제공한 그룹 디렉터리·레벨 pool·세그먼트 node
pool을 초기화한다. 그룹은 group ID로 정렬하고, 각 그룹은 최신 레벨부터
아래로 연결한다. 같은 레벨의 세그먼트 범위는 정렬·비중첩을 유지한다.
서로 다른 레벨의 범위는 겹칠 수 있다.

그룹 디렉터리에는 현재 RAM에 등록된 그룹만 들어간다. 전체 LPN 수만큼의
정답 map을 실제 인덱스 내부에 두지 않는다. pool은 호출자가 소유하며,
동적 메모리 할당이나 firmware 고정 주소 배치는 하지 않는다.

**2. 새 매핑 삽입과 레벨 이동**

`LeaFtlIndexInsert()`는 2번 학습 모듈이 생성한 한 그룹의 세그먼트 묶음을 받는다.
한 호출 내의 세그먼트는 시작 offset으로 정렬되고 범위가 서로 겹치지 않아야 한다.
성공한 삽입은 해당 그룹의 모든 이전 삽입보다 최신이다.

- 새 세그먼트는 Level 0에 삽입한다.
- 기존 Level 0에서 새 범위와 겹치는 세그먼트만 분리한다.
- 분리한 기존 세그먼트들을 새 Level 1에 배치하고, 기존 하위 레벨보다 앞에 연결한다.
- 관련 없는 Level 0 세그먼트는 그대로 유지한다.
- 새 범위가 기존 Level 0과 전혀 겹치지 않으면 추가 레벨을 만들지 않는다.

겹침은 실제 LPN 소속뿐 아니라 범위로 판정한다. sparse segment의 hole에
새 singleton을 넣어도 같은 레벨의 범위 비중첩을 위해 기존 segment를 옮긴다.
기존 매핑을 삭제하거나 기울기·절편을 수정하지 않으므로 이전 레벨에 남은
다른 유효 LPN은 계속 조회할 수 있다.

이번 단계는 merge·compaction 없이 레벨을 쌓는다. 논문처럼 이전 세그먼트의
불필요한 주소를 줄이거나 완전히 가려진 세그먼트를 없애는 작업은 4번에서 수행한다.

**3. 최신 매핑 우선 조회와 hole 처리**

`LeaFtlIndexLookup()`은 LPN으로 그룹을 계산하고 정렬 디렉터리를 이진 탐색한다.
그룹의 Level 0부터 오래된 레벨 순서로 탐색하며, 실제 LPN 소속을 만족하는
첫 세그먼트의 PPN을 반환한다.

한 레벨 안에서는 segment slot들을 균형 이진 탐색 트리로 연결한다.
삽입 후 해당 레벨의 정렬 목록으로 트리를 다시 구성하여 편향을 방지한다.
조회는 그룹당 `O(log G)`, 레벨마다 범위 탐색 `O(log S)`이며 레벨 수의 영향을 받는다.
같은 node의 정렬 linked list도 유지하여 이후 compaction 순회에 사용할 수 있게 했다.

예를 들어 이전 레벨이 LPN 0..63을 표현하고 최신 레벨이 `[16,18,...,30]`을
표현하면, LPN 18은 최신값을 반환하고 LPN 17은 최신 범위의 hole이므로
이전 레벨로 내려가 기존 값을 반환한다. 범위가 겹쳤다는 이유로 오래된 유효 값을
가리거나 MISS를 조기에 반환하지 않는다.

PPN 0은 정상 매핑으로 취급한다. `0xffffffff` LPN은 INVALID로 처리하며
0xfffffffe LPN/PPN을 보존한다. MISS·INVALID에서 PPN 출력은 바꾸지 않는다.

**4. 자원 상한과 삽입 실패 시 원자성**

초기화 시 실제 pool 용량을 설정하고 1번 설정의 상한 이내인지 확인한다.
삽입 전에 입력 모델·그룹·정렬·범위·총 node 잔여량·group 잔여량·level 잔여량과
그룹별 segment/level 상한을 모두 검사한다.

자원이 부족하면 NO_SPACE를 반환한다. 잘못된 입력은 INVALID로 거부한다.
두 경우 모두 디렉터리·pool·free list·카운터·기존 매핑을 변경하지 않는다.
실패 시 일부 최신 매핑만 발행되거나 기존 값을 잃는 동작을 방지한다.
호출자가 전달한 세그먼트는 복사하므로 이후 입력 배열을 재사용할 수 있다.

현재는 pool 반환·eviction·compaction이 없으므로 오래된 버전도 자원 사용량에
포함한다. 한도에 도달했을 때 오류를 숨기거나 오래된 값을 대신 성공 반환하지 않는다.

### 수정 후 검증 결과

MSVC C11 `/W4 /WX /fp:strict`에서 debug(`/Od /Zi`)와 optimized(`/O2`)
빌드 모두 경고 없이 컴파일하고 테스트를 통과했다.

- 4,000번의 결정적 난수 갱신 시도 후 매번 8개 그룹의 256개 LPN 전체를 정답 map과
  비교했다. 성공한 갱신과 자원 부족으로 거부된 갱신을 모두 포함한다.
- 경계·오류 등 지정 테스트를 포함해 총 8,284,160번의 정답 조회 대조를 수행했다.
- 반복 overwrite, 3개 이상 레벨, 최신 sparse segment의 hole에서 하위 레벨 조회,
  hole에 새 singleton 삽입, 여러 기존 segment를 동시에 밀어내는 삽입을 검사했다.
- 그룹 디렉터리의 순서 변경, 서로 다른 그룹의 독립성, 비중첩 삽입 시 레벨 수 유지,
  그룹 경계 255/256, PPN 0 및 최대 유효 LPN/PPN을 검사했다.
- 입력 배열을 바꿔도 이미 삽입한 모델이 영향을 받지 않음을 확인했다.
- group/level/node pool 부족, 그룹별 최대 level/segment 제한과 잘못된 batch를
  검사했다. 거부 전후 전체 상태를 byte 단위로 비교하여 미변경을 확인했다.
- 정답 조회와 별도로 모든 레벨의 목록 정렬·범위 비중첩, tree 중위 순회와 목록의
  일치, 균형 높이, node/level 고유 소유권, 카운터 일치와 active/free pool의 완전한
  분할을 검사했다. 링크 순환·중복·유실도 이 검사로 탐지한다.

기존 2번 모델을 그대로 링크하여 학습 결과를 인덱스에 넣는 통합 테스트를 수행했다.
정답 map은 테스트 전용이고 생산 모듈에는 들어가지 않는다.

### 메모리·타깃 제약과 남은 작업

테스트한 MSVC x64의 크기는 group 16 bytes, level 16 bytes,
node 40 bytes, index handle 64 bytes이다. node에는 24-byte 런타임 모델과
정렬/트리 링크·alignment가 포함된다. pool 수에 이 크기와 부가 비용을 곱하여
6번에서 타깃 DRAM·스택 예산을 계산해야 한다.

tree 재구성은 별도의 256개 임시 배열 없이 수행한다. 한 레벨에 비중첩 범위는
최대 256개이므로 재귀 깊이는 nonempty node 기준 최대 9이다. 실제 타깃 스택
비용은 후속 확인 대상이다. 현재 API는 단일 실행 흐름을 전제로 하며 외부에서
pool을 바꾸거나 삽입 중 조회를 병행하는 동작을 지원하지 않는다.

현재 MISS는 RAM 인덱스에서 못 찾았다는 의미다. Flash cache miss와 미기록 LPN을
구분하는 통합은 후속 Flash backing 단계에서 구현한다. 초기화는 RAM 상태를
의도적으로 비우며, 전원 장애 복구가 아니다. tombstone/unmap도 이번 범위에 없다.

SDK 전체 빌드와 보드 업로드는 수행하지 않았다. 다음 4번은 merge·compaction이다.
8-byte 저장 형식, SSD 타깃에 따른 고정소수점 전환 가능성, 보드 테스트
13·17·19번 이후 일정은 이전 합의대로 유지한다.


## 4번 — merge·compaction과 오래된 매핑 정리

기록일: 2026-11-12

### 목적과 변경 파일

3번의 다중 레벨 인덱스에서 최신 매핑에 가려진 이전 LPN을 제거하고,
남은 유효 주소를 보존하면서 세그먼트·레벨을 재배치하고 pool 공간을 반환한다.

- 수정: `firmware/leaftl/src/leaftl_index.h` — group compaction API, caller-owned workspace, 결과 구조체
- 수정: `firmware/leaftl/src/leaftl_index.c` — 실제 membership 차집합, 생존 구간 분할,
  호환 세그먼트 merge, 레벨 재배치와 node/level 반환
- 수정: `tests/test_leaftl_index.c` — compaction 전후·오류·공간 재사용·무작위 갱신 검증
- 수정: [tests/README.md](../../firmware/LeaFTL/tests/README.md) — 현재 동작·제약·테스트 실행 방법
- 수정: 이 구현 보고서

2번 부동소수점·float16 모델과 1번 설정은 그대로 사용한다.
기존 DFTL 실행 경로에 연결하거나 보드에 올리는 작업은 수행하지 않았다.

### 주요 구현 내용

**1. 최신 LPN만 남기는 membership 정리**

`LeaFtlIndexCompactGroup()`를 추가했다. 대상 그룹의 최신 레벨부터 오래된 레벨
순서로 순회하며 256-bit bitmap으로 실제 포함 LPN을 기록한다.
이미 최신 세그먼트가 가진 LPN은 오래된 세그먼트에서 제외한다.
범위 전체를 기록하지 않으므로 최신 segment의 hole 때문에 이전 유효 LPN이
잘못 제거되지 않는다. 정답 PPN 배열이나 NAND의 원본 데이터를 사용하지 않는다.

예를 들어 최신 segment가 `[0,2,4,...,62]`를 표현하고 이전 segment가 `0..63`을
표현하면, 이전 segment에서는 홀수 LPN만 남긴다. compaction 후에는 기록된
각 LPN을 표현하는 실제 membership이 전체 레벨에서 정확히 하나만 존재한다.

**2. 기존 계수를 보존한 분할과 merge**

생존 LPN을 규칙적인 stride 구간으로 나눈다. 여러 점이 남는 구간의 저장된
float16 기울기 K와 double 절편 I는 변경하지 않는다. stride는 실제 생존 주소에
맞춰 다시 정하므로 홀수만 남으면 stride 2로 표현할 수 있다.

한 점만 남으면 기존 모델로 정확한 PPN을 조회한 뒤 K=0, I=PPN인 singleton으로
정규화한다. 이 경우는 계수 비트 유지 대신 동일한 주소값 보존을 보장한다.

생존 세그먼트를 시작 offset으로 정렬한 뒤, 인접한 두 구간의 K/I가 같고
membership의 합집합이 정확한 등간격 수열일 때만 merge한다.
새로 회귀하거나 오차를 허용하여 합치지 않는다. 중간에 기록되지 않은 LPN을
만들지 않으며, 전역 최소 세그먼트 수를 보장하는 최적화는 아니다.

**3. 레벨 재배치**

정렬한 세그먼트를 범위가 겹치지 않는 레벨에 순서대로 배치한다.
같은 레벨은 범위 비중첩, 서로 다른 레벨은 범위 중첩 허용이라는 3번의 규칙을
유지한다. 전체 membership에서 중복 버전을 이미 제거했으므로 이 재배치가
최신 매핑 선택을 바꾸지 않는다. 레벨별 균형 탐색 트리도 다시 구성한다.

홀수와 짝수 segment처럼 실제 LPN 집합은 달라도 시작~끝 범위가 겹치는 경우에는
정리 후에도 여러 레벨을 사용한다. 모든 그룹을 무조건 한 레벨로 바꾸지 않는다.

**4. pool 반환과 실패 시 기존 상태 보존**

생존 세그먼트 목록과 레벨 배치를 caller-owned workspace에 먼저 만든다.
계획이 완료되면 기존 대상 그룹이 사용하던 node·level 수를 반환 가능한 공간으로
계산하여 자원 상한을 확인한다. 여유 pool이 0이어도 같은 그룹의 기존 공간을
재사용해 compaction할 수 있다.

성공 가능한 경우에만 기존 node/level을 free list로 반환하고 계획한 구조를
만든다. 다른 그룹의 소유 node·level과 매핑은 그대로 유지한다.
반환된 슬롯을 이후 삽입에서 다시 할당할 수 있다.

중간 overwrite로 이전 세그먼트가 두 조각으로 나뉘면 필요한 모델 수가 증가할
수 있다. 예를 들어 `0..63`과 최신 `16..31`을 정리하면 이전 `0..15`, 최신
`16..31`, 이전 `32..63`의 세 구간이 필요할 수 있다.
필요한 공간이 없으면 NO_SPACE를 반환하고 전체 인덱스·기존 매핑·결과 구조체를
변경하지 않는다. workspace 내용은 실패 시에도 변경될 수 있다.

존재하지 않는 그룹은 MISS, 잘못된 인자는 INVALID로 처리한다.
반환 결과에는 정리 전후 segment 수와 level 수를 기록한다. 결과 포인터는
선택 사항이며 NULL이면 통계 결과를 쓰지 않고 정리를 수행한다.

### 검증 결과

MSVC C11 `/W4 /WX /fp:strict`로 debug(`/Od /Zi`)와 optimized(`/O2`)
빌드를 수행했고 경고 없이 모든 테스트를 통과했다.

- 기존 3번의 4,000개 무작위 갱신 테스트를 유지하고 compaction과 섞인 추가
  3,000개 순차/희소 갱신을 검사했다. 무작위 갱신 시도 총 7,000회이다.
- helper로 검증한 compaction 3,893회와 각 갱신 뒤에 정답 map을 대조했다.
  전체 suite에서 총 22,407,168번의 LPN 조회 비교를 수행했다.
- 정리한 그룹의 모든 세그먼트 membership을 별도로 열거하여 기록된 LPN은
  정확히 1개 소유자, 미기록 hole은 0개 소유자임을 확인했다.
- 전체 overwrite로 이전 모델 제거, 중간 overwrite 분할, 동일 계수 merge,
  홀수/짝수 interleaving, hole의 singleton 갱신, 여러 레벨을 유지하는 배치를 검사했다.
- 여러 점 생존 모델의 K/I 비트 보존과 한 점 생존 모델의 주소 보존을 확인했다.
  음수 기울기와 큰 PPN, PPN 0, 최대 유효 LPN/PPN도 포함한다.
- 반복 compaction의 조회 결과 보존, 다른 그룹 독립성, 잘못된 인자,
  미등록 그룹과 선택 결과 포인터를 검사했다.
- node 2개인 pool에서 3개가 필요한 계획을 거부하고, 거부 전후 전체 인덱스와
  결과 구조체가 byte 단위로 같음을 확인했다.
- node/level pool이 모두 가득 찬 상태에서 6개 버전을 1개로 정리하고,
  회수한 슬롯에 후속 갱신을 다시 삽입해 공간 재사용을 확인했다.
- 기존 레벨 정렬·비중첩, tree 균형, linked list 일치, node/level 소유권과
  active/free pool 완전 분할 검사도 함께 수행했다.

### 메모리·적용 범위와 다음 단계

현재 MSVC x64의 compaction workspace는 7,712 bytes이다.
후보 모델·레벨 배치 정보·256-bit membership bitmap이 포함되며,
지속적으로 보관하는 full mapping/reference map은 아니다.
호출자가 제공하고 인덱스가 보관하지 않는다. 실제 firmware에서는 6번 메모리
예산을 확인하기 전에 이 workspace를 스택에 할당하지 않는다.

런타임 segment 24 bytes, node 40 bytes 등 기존 표현은 유지한다.
전체 8-byte 저장 형식과 타깃에 따른 고정소수점 전환은 후속 작업이다.

이번 API는 한 resident 그룹의 gamma=0 명시적 정리이다. Insert가 자동으로
compaction하지 않으며, 필요 시 호출자가 정리 후 삽입을 다시 요청한다.
여러 그룹 전체를 묶는 원자적 트랜잭션, tombstone/unmap, Flash/NAND I/O,
전원 장애 복구와 펌웨어 스케줄링은 이번 범위가 아니다.

다음 5번에서 주소 변환과 이 인덱스 사이의 통합 매핑 인터페이스를 구현한다.
SDK 전체 빌드와 보드 테스트는 아직 수행하지 않았으며, 보드 테스트는 합의한
13번·17번·19번 뒤 일정으로 유지한다.
